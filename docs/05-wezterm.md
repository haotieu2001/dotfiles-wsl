# 05 - WezTerm and the Windows/WSL config bridge

The video's 15:33 chapter. The config itself is nearly unchanged; what changes
completely is *where it lives and how it gets loaded*.

## The problem

WezTerm is the program that opens a window, rasterizes glyphs, and receives your
keystrokes. All of that is Windows work. So WezTerm is a **Windows process**,
even though everything it displays is running inside the Linux VM.

That creates a config problem. The natural approach - keep `wezterm.lua` in the
repo and symlink `~/.config/wezterm` to it, as `home.nix` does for Neovim and
herdr - cannot work:

1. WezTerm on Windows never reads the Linux `~/.config`.
2. Symlinks created inside WSL under `/mnt/c` are WSL-only constructs. Windows
   applications do not follow them.

Three ways out, and why this repo picks the third:

| Approach | Problem |
| --- | --- |
| Copy the config to Windows on every rebuild | Two copies, guaranteed to drift. Edits made on the Windows side are silently lost on the next sync. |
| Create a real Windows symlink to the WSL path | Works, but needs Developer Mode or an elevated shell, and breaks if the distro is renamed. |
| **A loader stub on Windows that reads the WSL file** | No admin, one source of truth, hot reload preserved. |

## The stub

`setup-windows.ps1` writes this to `%USERPROFILE%\.wezterm.lua`:

```lua
-- Generated by dotfiles-wsl/windows/setup-windows.ps1 - do not edit.
local wezterm = require 'wezterm'
local wsl_config = [[\\wsl.localhost\Ubuntu-26.04\home\you\dotfiles-wsl\home\.config\wezterm\wezterm.lua]]
wezterm.add_to_config_reload_watch_list(wsl_config)
return dofile(wsl_config)
```

- `[[...]]` is a Lua long string, so the backslashes need no escaping.
- `\\wsl.localhost\<distro>\...` is the UNC path Windows uses to reach the Linux
  filesystem. It is a real, supported bridge, not a mount hack.
- `add_to_config_reload_watch_list` is the important line. WezTerm watches its
  main config for changes; without this it would watch only the stub, which
  never changes, and you would lose the hot reload the video demonstrates at
  16:52. With it, saving `wezterm.lua` inside WSL updates the terminal live.
- `dofile` executes the real config and returns its table.

The script derives the UNC path from `$PSScriptRoot`, so running it from inside
the WSL filesystem needs no arguments at all.

Because the target lives in the repo, `git status` still sees your edits. The
edit-in-place property from the video survives the platform boundary.

## `home/.config/wezterm/wezterm.lua`, line by line

```lua
local wezterm = require("wezterm")
```

The API module.

```lua
local WSL_DISTRO = "Ubuntu-26.04"
```

**Change this if your distro differs.** Get the exact name from PowerShell with
`wsl -l -q`. A mismatch means WezTerm opens on a domain that does not exist.

```lua
local config = wezterm.config_builder()
```

Returns a config table that validates keys as you set them, so a typo produces a
clear error rather than being ignored.

```lua
config.wsl_domains = {
  {
    name = "WSL:" .. WSL_DISTRO,
    distribution = WSL_DISTRO,
    default_cwd = "~",
  },
}
config.default_domain = "WSL:" .. WSL_DISTRO
```

The section with no macOS counterpart. On macOS WezTerm just runs your login
shell; on Windows it would open PowerShell.

`wsl_domains` declares which WSL distros WezTerm can spawn into, and
`default_domain` makes one of them the default for new windows and tabs. The
`WSL:` prefix is the naming convention WezTerm uses for auto-discovered domains.

Declaring `wsl_domains` explicitly **replaces** WezTerm's auto-discovered list.
That is intentional: it lets us set `default_cwd = "~"` so new tabs start in the
fast Linux home directory rather than `/mnt/c/Users/<you>` on the slow 9p mount.

```lua
config.color_scheme = "rose-pine-moon"
config.font = wezterm.font("Hack Nerd Font")
```

Unchanged from the video. The font name must match what Windows registered;
`setup-windows.ps1` registers it as `Hack Nerd Font`.

```lua
config.font_size = 12.0
```

The video uses `15.0`, a macOS Retina value. On a typical 1080p or 1440p Windows
display 12.0 is about the same physical size. Adjust to taste; it hot-reloads.

```lua
config.window_background_opacity = 0.9
config.win32_system_backdrop = "Acrylic"
```

`macos_window_background_blur = 50` from the video has no effect on Windows. The
equivalent is a system backdrop: `"Acrylic"` is the frosted blur,`"Mica"` tints
from your wallpaper, `"Auto"` lets Windows decide. It needs
`window_background_opacity < 1.0` to be visible at all.

For the blur to show through Neovim, the colorscheme must not paint an opaque
background - see the `transparency` setting in
[06-neovim.md](06-neovim.md).

```lua
config.hide_tab_bar_if_only_one_tab = true
config.window_decorations = "RESIZE"
```

Unchanged. `"RESIZE"` drops the title bar and keeps the resize borders, giving
the frameless window from 17:20. On Windows this also removes the min/max/close
buttons, so close with `alt+F4` or `exit`.

```lua
return config
```

WezTerm expects the config table as the file's return value.

## Alternative: WezTerm inside WSL via WSLg

You can install WezTerm as a Linux package (add `wezterm` to `home.packages`) and
let WSLg display it. Then the standard symlink approach works and the Windows
scripts become unnecessary.

Not the default here because WSLg adds a compositing layer that costs latency
and can interfere with GPU acceleration, and because a Windows-native WezTerm
integrates better with the rest of the desktop. If you prefer it: add the
package, add `nerd-fonts.hack` to `home.packages`, add a `home.file` symlink for
`.config/wezterm` matching the Neovim one, and delete the `wsl_domains` block.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| Boxes instead of icons | Font not installed on Windows. Re-run `setup-windows.ps1`, then sign out and back in. |
| Opens PowerShell, not WSL | `WSL_DISTRO` does not match `wsl -l -q`. |
| Background is opaque | `win32_system_backdrop` needs opacity < 1.0; also check the Neovim `transparency` setting. |
| Edits do not hot-reload | The stub is missing `add_to_config_reload_watch_list`; re-run `setup-windows.ps1`. |
| `dofile` error on startup | The UNC path is wrong, usually after renaming the distro or moving the repo. Re-run `setup-windows.ps1`. |
