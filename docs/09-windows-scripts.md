# 09 - The Windows scripts

Two PowerShell scripts covering what Nix cannot reach from inside WSL. Neither
needs administrator rights.

---

# `windows/setup-windows.ps1`

Installs WezTerm, installs Hack Nerd Font, and writes the loader stub.

## Parameters

```powershell
param(
  [string]$Distro,
  [string]$WslUser
)
```

Both usually unnecessary - see below.

## Locating the repo

```powershell
$repoRoot = Split-Path -Parent $PSScriptRoot

if ($repoRoot -like '\\wsl*') {
  Ok "Running from inside WSL: $repoRoot"
}
```

The neat part. If you launched the script from the WSL filesystem, for example

```
\\wsl.localhost\Ubuntu\home\you\dotfiles-wsl\windows\setup-windows.ps1
```

then `$PSScriptRoot` is *already* the UNC path Windows needs. Nothing has to be
guessed, and the distro name and username come along for free.

```powershell
} else {
  if (-not $Distro)  { $Distro  = (wsl.exe -l -q | Where-Object { $_.Trim() } | Select-Object -First 1).Trim() }
  if (-not $WslUser) { $WslUser = (wsl.exe -d $Distro -e whoami).Trim() }
  $realPath = (wsl.exe -d $Distro -e readlink -f "/home/$WslUser/.dotfiles").Trim()
  $repoRoot = "\\wsl.localhost\$Distro" + ($realPath -replace '/', '\')
}
```

The fallback when the script was copied onto the Windows drive. It shells into
WSL to ask for the distro name, the username, and where `~/.dotfiles` actually
points.

`readlink -f` is important: `~/.dotfiles` is a symlink created by `bootstrap.sh`,
and the `\\wsl.localhost` bridge does not reliably follow Linux symlinks, so the
link is resolved to a real path on the Linux side first.

The `-replace '/', '\'` converts POSIX separators to Windows ones.

```powershell
$weztermConfig = Join-Path $repoRoot 'home\.config\wezterm\wezterm.lua'
if (-not (Test-Path $weztermConfig)) { throw "Expected config not found at $weztermConfig" }
```

Fail early with a useful message rather than writing a stub that points nowhere.

## WezTerm

```powershell
if (Get-Command wezterm.exe -ErrorAction SilentlyContinue) {
  Ok 'already installed, skipping'
} elseif (Get-Command winget.exe -ErrorAction SilentlyContinue) {
  winget install --id wez.wezterm --exact --source winget `
    --accept-package-agreements --accept-source-agreements
}
```

Idempotent. `--exact` prevents winget matching a similarly named package, and
the two `--accept-*` flags keep it non-interactive.

This is the weakest link in reproducibility: winget resolves its own version, so
unlike a Nix package this is not hash-pinned. Pin explicitly with
`--version <x.y.z>` if that matters to you.

## The font

```powershell
$fontDir = Join-Path $env:LOCALAPPDATA 'Microsoft\Windows\Fonts'
$fontReg = 'HKCU:\Software\Microsoft\Windows NT\CurrentVersion\Fonts'
$faces   = @('Regular', 'Bold', 'Italic', 'BoldItalic')
```

A **per-user** font install. The system-wide location (`C:\Windows\Fonts` plus
`HKLM`) needs admin; `LOCALAPPDATA` plus `HKCU` does not, and Windows treats
both as first-class.

```powershell
$missing = $faces | Where-Object { -not (Test-Path (Join-Path $fontDir "HackNerdFont-$_.ttf")) }
if (-not $missing) { Ok 'all four faces already present, skipping' }
```

Skips an 18MB download when the font is already installed.

```powershell
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
Invoke-WebRequest -Uri $url -OutFile $zip -UseBasicParsing
```

Windows PowerShell 5.1 still defaults to TLS 1.0, which GitHub refuses. Without
that line the download fails with an unhelpful "underlying connection was
closed". `-UseBasicParsing` avoids a dependency on Internet Explorer's engine.

Only the four `HackNerdFont-*.ttf` faces are extracted. `Hack.zip` contains
twelve files, including `Mono` and `Propo` variants that WezTerm is not asked
for here.

```powershell
    Copy-Item $file $dest -Force
    $label = if ($face -eq 'Regular') { 'Hack Nerd Font (TrueType)' } else { "Hack Nerd Font $face (TrueType)" }
    New-ItemProperty -Path $fontReg -Name $label -Value $dest -PropertyType String -Force | Out-Null
```

Copying the file is not enough - Windows only enumerates a font once it is
registered. Per-user entries take the full path as their value, where system
entries take a bare filename.

Note `else` sits on the same line as the closing brace. A newline before `else`
ends the statement and is a syntax error in PowerShell.

Newly registered fonts sometimes are not visible to already-running processes,
hence the sign-out hint.

## The stub

```powershell
$stub = @"
-- Generated by dotfiles-wsl/windows/setup-windows.ps1 - do not edit.
local wezterm = require 'wezterm'
local wsl_config = [[$weztermConfig]]
wezterm.add_to_config_reload_watch_list(wsl_config)
return dofile(wsl_config)
"@
```

`@"..."@` is an expandable here-string, so `$weztermConfig` is interpolated
while the Lua `[[...]]` brackets pass through untouched.

```powershell
if ((Test-Path $stubPath) -and -not ((Get-Content $stubPath -Raw) -match 'setup-windows\.ps1')) {
  Copy-Item $stubPath "$stubPath.backup" -Force
}
Set-Content -Path $stubPath -Value $stub -Encoding UTF8
```

If a `.wezterm.lua` already exists and does **not** carry this script's marker
comment, it was hand-written and gets backed up before being replaced. A stub
this script wrote earlier is overwritten silently, keeping re-runs quiet.

Why this design at all is covered in [05-wezterm.md](05-wezterm.md).

# `windows/settings.ps1`

The counterpart of the video's `system.defaults`. Optional; nothing depends on it.

```powershell
[CmdletBinding(SupportsShouldProcess)]
```

Gives the script `-WhatIf`, so `.\settings.ps1 -WhatIf` prints every change
without making one. Worth using first.

```powershell
function Set-Reg {
  [CmdletBinding(SupportsShouldProcess)]
  param($Path, $Name, $Value, $Type = 'DWord')
  if (-not (Test-Path $Path)) { New-Item -Path $Path -Force | Out-Null }
  if ($PSCmdlet.ShouldProcess("$Path\$Name", "set to $Value")) {
    New-ItemProperty -Path $Path -Name $Name -Value $Value -PropertyType $Type -Force | Out-Null
  }
}
```

The helper. It needs its own `[CmdletBinding(SupportsShouldProcess)]`: a plain
function has no `$PSCmdlet`, so `-WhatIf` would not reach it and the preview
would lie.

`New-Item` first, because some of these keys do not exist on a fresh install.

## The settings

```powershell
Set-Reg $personalize 'AppsUseLightTheme'    0
Set-Reg $personalize 'SystemUsesLightTheme' 0
```

macOS `AppleInterfaceStyle = "Dark"`. Two values because Windows themes apps and
system surfaces separately.

```powershell
Set-Reg $keyboard 'KeyboardSpeed' '31' 'String'
Set-Reg $keyboard 'KeyboardDelay' '0'  'String'
```

macOS `KeyRepeat = 2` and `InitialKeyRepeat = 15`. **Both scales are inverted
relative to macOS**: on Windows `KeyboardSpeed` runs 0..31 with 31 fastest, and
`KeyboardDelay` runs 0..3 with 0 shortest. They are stored as strings, not
DWORDs, which is why `$Type` is overridden.

```powershell
Set-Reg $advanced 'HideFileExt' 0
Set-Reg $advanced 'Hidden'      1
Set-Reg $advanced 'HideIcons'   1
```

Show extensions (macOS `AppleShowAllExtensions`), show hidden files, and hide
desktop icons (macOS `finder.CreateDesktop = false`).

```powershell
Set-Reg $touchpad 'TapsEnabled' 1
```

macOS `trackpad.Clicking = true`. Precision Touchpad drivers only; no effect on
a desktop.

```powershell
$settings = (Get-ItemProperty -Path $stuck -Name Settings).Settings
if ($settings[8] -band 1) { Ok 'already auto-hiding' }
else {
  $settings[8] = $settings[8] -bor 1
  Set-ItemProperty -Path $stuck -Name Settings -Value $settings
}
```

Taskbar auto-hide, standing in for both `dock.autohide` and `_HIHideMenuBar`
since Windows has one bar doing both jobs.

`StuckRects3\Settings` is an opaque binary blob holding several unrelated taskbar
properties, with auto-hide as bit 0 of byte 8. So this is a read-modify-write:
`-band 1` tests the bit, `-bor 1` sets it while leaving everything else intact.
Overwriting the whole blob with a known-good value is the common shortcut and it
resets taskbar position and size as a side effect.

```powershell
Stop-Process -Name explorer -Force -ErrorAction SilentlyContinue
```

Explorer caches these values and must restart. Windows normally relaunches it
automatically; the script starts it manually if that does not happen.

## What is deliberately absent

`finder.FXPreferredViewStyle = "Nlsv"` has no faithful equivalent. Explorer
stores per-folder view state in `BagMRU`/`Bags`, an undocumented cache, so
setting a global default reliably is not possible. Left alone rather than
written badly.

## Honesty about reproducibility

These are imperative registry writes. Nothing reverts a change you later make in
the Settings app, and there is no equivalent of `homebrew.onActivation.cleanup =
"zap"` here. Re-running reasserts the values; that is the entire guarantee. The
Nix half of this repo is genuinely reproducible, and this script is not, which is
why it is isolated in its own optional file.
